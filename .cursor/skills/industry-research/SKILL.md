# 行业深度研究

基于用户输入的 **行业、论文、热点、产业链** 四个锚点，产出可在线浏览的产业链与投资研究 HTML 报告，写入 `stock/public/`。

参考范例：[h200-industry-chain.html](../../stock/public/h200-industry-chain.html)

## 用户输入（四锚点）

| 锚点 | 用途 |
|------|------|
| **行业** | 界定研究边界、竞争格局、监管与周期属性 |
| **论文** | 提取技术路线、成本结构、效率极限、关键假设；标注论文发表时间与是否已被产业验证 |
| **热点** | 当前市场叙事、政策催化、供需缺口、资金偏好 |
| **产业链** | 上中下游环节划分、价值分配、瓶颈环节、国产替代/出海节点 |

四者缺一时，先从已有信息推断并在报告 header 标注「待补充」；**禁止**在缺输入时编造具体论文结论或产业链环节。

## 工作流

```
Task Progress:
- [ ] 1. 确认四锚点，生成 slug 与输出文件名
- [ ] 2. 论文解读：核心贡献、数据、局限、产业映射
- [ ] 3. 热点与政策检索（必做，WebSearch）
- [ ] 4. 产业链与成本拆解：总体 + 细分链条
- [ ] 5. 国内外核心上市公司 mapping + 多维度对比
- [ ] 6. 景气度研判：1-5 年 + 短/中/长期
- [ ] 7. 投资机会与跟踪优先级
- [ ] 8. A 股重点公司可选跑 stock-analysis 抓数（见下）
- [ ] 9. 按 template 写入 stock/public/{slug}.html
- [ ] 10. 注册 public-html.ts / 站点导航（新报告时）
```

### 1. 输出命名

```text
stock/public/{slug}.html
```

- `slug`：英文小写 + 连字符，如 `solid-state-battery-industry-chain`、`copper-ai-datacenter-industry-chain`
- 与现有文件不重名；优先 `{主题}-industry-chain.html` 或 `{主题}-industry-research.html`

### 2. 论文解读（必做）

从用户给定论文出发：

1. **一句话贡献**：解决了什么问题
2. **方法与数据**：样本、假设、关键公式或实验结论
3. **成本/效率含义**：对产业链哪一环的 BOM、良率、能耗、CAPEX 有影响
4. **验证状态**：实验室 / 中试 / 量产 / 已被推翻
5. **投资映射**：利好或利空哪些环节；**不**把论文潜力直接写成已兑现订单

### 3. 热点与政策检索（必做）

**必搜模板**（替换 `{行业}` `{热点}` `{分析日期}`）：

```text
{行业} {分析日期} 政策 OR 补贴 OR 出口管制 OR 产能
{热点} {分析日期} 龙头 OR 订单 OR 涨价 OR 技术突破
{产业链关键环节} 成本 OR 良率 OR 产能利用率 {分析日期}
```

**信源优先级**（高 → 低）：

1. 官方规格、监管文件、上市公司公告/年报/问询回复
2. 龙头公司 IR、供应链签核披露
3. TrendForce、Gartner、IEA 等产业研究
4. 主流财经媒体（须交叉验证）
5. 自媒体、传闻 — **不得**作为「确认供货/订单」依据

### 4. 成本拆解

必须包含两层：

| 层级 | 内容 |
|------|------|
| **总体成本** | 终端产品/服务 TCO 或 BOM 100% 分布；给区间而非假精确 |
| **细分链条** | 各环节的 value share、毛利率特征、瓶颈、价格弹性 |

成本标注规则（与 h200 范例一致）：

- 区间表达：`约 X-Y%` / `约 A-B 万美元`
- 无法确认时写「待验证」并说明缺什么数据
- EDA/设备/材料等间接成本，说明摊入路径而非强行塞进单机 BOM

### 5. 上市公司 mapping

**国际 + 国内** 分列，每家公司至少包含：

| 维度 | 要点 |
|------|------|
| 环节卡位 | 在链条哪一环、角色（平台方/OEM/材料/设备） |
| 护城河 | 规模、生态、转换成本、监管牌照、客户粘性 |
| 技术壁垒 | 专利、工艺 know-how、认证周期、良率 |
| 订单/能见度 | 在手订单、Backlog、大客户占比；区分「确认」与「预期」 |
| 业绩拐点 | 产能释放、毛利率拐点、费用率拐点、盈亏平衡点 |
| 戴维斯双击 | 盈利增速 ↑ + 估值扩张是否同时具备；触发条件 |
| 主要风险 | 技术路线被替代、客户集中、 capex 过度、政策 |

**证据标签**（HTML 内联样式，见 [reference.md](reference.md)）：

- `evidence-confirmed`：公告/官网/法说会确认
- `evidence-indirect`：产业链高相关但未点名客户
- `evidence-private`：未披露，仅行业推断 — 不得写确定供货

A 股公司额外标记：`ashare` + 重要者 `ashare-key`。

### 6. 景气度研判

必须覆盖三个时间尺度 + 1-5 年展望：

| 尺度 |  horizon | 关注变量 |
|------|----------|----------|
| **短期** | 0-12 月 | 库存、价差、订单、政策落地、产能投产节奏 |
| **中期** | 1-3 年 | 资本开支周期、渗透率 S 曲线、竞争格局固化 |
| **长期** | 3-5 年+ | 技术路线终局、单位成本学习曲线、替代品威胁 |

**1-5 年景气度**：用「上行 / 震荡 / 下行」+ 置信度（高/中/低）+ 核心驱动 3 条以内。

### 7. 投资机会

按环节给出：

1. **首选跟踪**（瓶颈 + 验证度高）
2. **弹性标的**（小市值/高 beta，须标注风险）
3. **预期差**（市场定价 vs 调研结论）
4. **回避/谨慎**（产能过剩、技术路线 loser、估值透支）

### 8. A 股抓数（可选但推荐）

对报告中标记为 `ashare-key` 的 **≤5 只** A 股，可调用 [stock-analysis](../stock-analysis/SKILL.md) 工作流：

```bash
python .cursor/skills/stock-analysis/scripts/fetch_stock.py {代码} --market-context --pretty
node stock-cli/dist/cli.js {代码} --json   # 仅 A 股
```

将 PE、ROE、涨跌幅、尾随止损等 **仅用于** 报告中的「上市公司对比表」与估值语境；**禁止**凭记忆填数。

### 9. 写入 HTML

完整结构、CSS、组件约定见 [reference.md](reference.md)。核心要求：

- 单文件 HTML，`lang="zh-CN"`，Tailwind CDN（与现有 public 页一致）
- Header 含：行业标签、更新日期、「公开资料估算/研究结论，非投资建议」
- 成本树用 `<details>` 折叠结构（见 h200 范例）
- 含：成本总览卡片、产业链树、景气度表、公司对比表、投资机会、来源、免责声明
- 术语首次出现附英文缩写（如 HBM（高带宽存储器））

### 10. 站点注册（新报告）

新 HTML 写入后，更新：

1. `stock/.vitepress/public-html.ts` — 加入路径
2. `stock/.vitepress/config.ts` — nav 可选增加入口
3. `stock/index.md` — features 可选增加卡片

本地预览：`cd stock && npm run dev` → `http://localhost:5173/{slug}.html`

## 质量检查

- [ ] 四锚点在 header 或专节中明确体现
- [ ] 论文结论与产业现状已区分「已验证 / 待验证」
- [ ] 成本为区间表达，注明信源与口径
- [ ] 国际 + 国内核心上市公司均已覆盖
- [ ] 含拐点、戴维斯双击、护城河、技术壁垒、订单等维度对比
- [ ] 短/中/长期 + 1-5 年景气度均已给出
- [ ] 无确认供货/订单臆测；证据标签使用正确
- [ ] 免责声明完整
- [ ] 新文件已加入 `public-html.ts`（若需站内直链）
