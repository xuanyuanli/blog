# weekly-rotation

ETF 周线轮动策略：每周最后一个交易日 14:30（上海时间）对比标的池近 4 个交易周的累计涨幅，取最高者——为正则持有它，为负则全部空仓，直到下一次轮动。持仓状态持久化到 `state.json`，决策结果通过 Server酱 推送。

| 创业板50ETF | `SZ159949` |

| 云计算ETF | `SZ159890` |
| 有色ETF | `SZ159652` |
| 卫星ETF | `SZ159206` |

实盘（daemon / once）默认使用全部 9 只。

## 策略规则

- 每 1 周的周五 14:30 轮动；若周五非交易日，则本周最后一个交易日轮动；若整周无交易日，顺延至下一周。
- 近 4 周累计涨幅 = 当前价 / 倒数第 4 个已完结周的收盘价 - 1。
- 涨幅最高者为正回报 → 持有它；为负回报 → 空仓至下次轮动。

## 用法

```bash
npm install
npm run build

# 常驻调度（服务器上由 systemd 拉起）
node dist/cli.js daemon

# 立即执行一次（--dry-run 只计算打印，不发通知、不写状态）
node dist/cli.js once --dry-run

# 回测：按成立时间分档对比三个标的池（全部 / 不含2025年新品 / 长历史）
node dist/cli.js backtest
node dist/cli.js backtest --start 2024-07-08            # 指定起点
node dist/cli.js backtest --start 2024-07-08 --end 2026-07-01

# 全组合回测：枚举全部标的子集（大小≥2），按累计收益与卡玛比率各出一个 Top 榜
node dist/cli.js combos
node dist/cli.js combos --end 2024-07-14 --top 15       # 去掉最近两年数据的稳健性对照
```

回测口径：以周收盘价近似周五 14:30 执行价，逐周复利，不计费率与滑点；不指定 `--start` 时每个池的起点取池内最晚成立 ETF 的上市周（对齐取交集，故新品越多窗口越短）。为兼顾窗口长度，分三档对比：全部 9 只（受卫星ETF 2025-03 限制）、7 只（剔除卫星/科创芯片，起点约 2023-03）、6 只（再剔除有色ETF，起点约 2021-06）。指标含累计收益、年化、最大回撤、换仓次数、空仓周数，并输出各标的同期买入持有收益作基准。

参考结果（截至 2026-07-10）：

| 标的池 | 区间 | 周数 | 累计收益 | 年化 | 最大回撤 |
| --- | --- | --- | --- | --- | --- |
| 9 只（全部） | 2025-05-09 ~ 2026-07-10 | 60 | +401.80% | 304.70% | 18.07% |
| 7 只（不含2025年新品） | 2023-03-10 ~ 2026-07-10 | 171 | +426.11% | 65.68% | 30.96% |
| 6 只（长历史） | 2021-06-25 ~ 2026-07-10 | 257 | +315.76% | 33.42% | 40.76% |

区间长度差异大，年化不可直接对比；长历史池回撤明显更深（40.76%），是对策略更真实的压力测试。

### 全组合回测（`combos`）

枚举全部标的子集（大小 ≥ 2，9 只共 502 个组合），每个组合在其自然对齐窗口内回测，分别按「累计收益」和「卡玛比率（年化/最大回撤）」输出 Top 榜。因各组合上市时间不同、对齐窗口长短不一，累计收益与年化会明显偏向窗口短的近期强势组合（含卫星/科创芯片的组合只有约 60 周、恰逢科技牛市），故务必结合区间与回撤判断，并用 `--end` 做去近端稳健性检验。

参考结论（截至 2026-07-10）：

- **全历史**：卡玛榜几乎被 2025-05 起约 60 周的近期组合霸榜（年化 300%+、卡玛 15+），是牛市 recency 偏差，不可当作长期预期。剔除这些短窗组合后，长窗口里表现稳健的是 `创业板50+通信`（346 周 +708%、卡玛 1.55）、`创业板50+科创50+通信`（284 周 +520%、卡玛 1.75）、`科创50+通信+云计算`（265 周 +485%、卡玛 2.07）。
- **去掉最近两年（`--end 2024-07-14`，剔除仍未上市的卫星/科创芯片）**：稳健性明显回落，卡玛头部为 `创业板50+通信`（243 周 +178.8%、卡玛 1.08）、`沪深300+创业板50+通信`（1.06）、`创业板50+科创50+通信`（0.86）。**「创业板50+通信」这一核心组合在两个区间都稳居前列**，是穿越周期相对可靠的骨架；多数含热门赛道的大杂烩组合在去掉近两年后卡玛跌到 0.6 以下。

> 备注：曾测试过「持有期内收盘跌破日线均线即卖出、空仓至下次轮动」的增强模式（MA5/MA10/MA20），在 2020-12 ~ 2026-07 的 283 周区间全部跑输基础策略且回撤更大（基础 392.85%/回撤 22.61%，MA20 280.96%、MA10 128.90%、MA5 109.84%，回撤均 28% 以上）。原因是动量策略持有的本就是强势 ETF，日常回调频繁触发误卖、随后又高位接回，均线越短磨损越重，故已移除该逻辑。

## 运行时配置

- 通知密钥从环境变量 `SERVERCHAN_SENDKEY` 读取（Server酱 SendKey，支持 Turbo 与 Server酱3），未设置则跳过通知。部署时 `bops rotation` 按优先级注入容器：服务器环境变量 `SERVERCHAN_SENDKEY` > bops 本地 conf（写远程 `.env`）。本地调试直接设置环境变量即可。
- `state.json`：当前持仓与轮动历史，由程序维护，位于数据目录（`--data-dir`，或环境变量 `WEEKLY_ROTATION_DIR`，默认当前目录）。容器内为 `/data`，挂载自宿主机 `/data/apps/weekly-rotation/data/`。

```bash
# 本地带通知运行示例（PowerShell: $env:SERVERCHAN_SENDKEY="SCTxxxx"）
SERVERCHAN_SENDKEY=SCTxxxx node dist/cli.js once
```

## 部署

由仓库的 `blog-ops` 以 Docker 方式部署（远程无需 Node 环境，需已安装 Docker）：

```bash
node blog-ops/bin/bops.js rotation
```

流程：本地构建 → 上传 `dist/` + `package.json` + `Dockerfile` 到服务器 `/data/apps/weekly-rotation/` → 远程 `docker build` → 重建容器 `weekly-rotation`（`--restart unless-stopped`，`.env` 注入环境变量，`data/` 挂载为 `/data` 持久化 `state.json`）。

服务器上常用命令：

```bash
docker logs -f weekly-rotation      # 查看日志
docker restart weekly-rotation      # 重启
cat /data/apps/weekly-rotation/data/state.json   # 查看持仓状态
```
